# Custom 10h Speaker-Domain Fix Design

## Problem

The Custom_10h pipeline preserves CAM++ labels as `Speaker 01`, `Speaker 02`, and so on when constructing ViT5 inputs. The ViT5 training corpus instead uses opaque labels such as `no.0` and `no.1`. Real-model ablation showed that the human-readable labels are copied or interpreted as semantic entities, producing hallucinated claims about “Speaker 01”.

## Design

Keep CAM++ output and persisted diarization artifacts unchanged for traceability. At the ViT5 boundary only, deterministically remap distinct speaker labels by first appearance to `no.0`, `no.1`, and so on. A single-speaker chunk therefore receives `no.0`; labels are not removed because the training formatter always emits `speaker: text`.

The remapping is topic-local at formatting time. This preserves each topic's equality relationships between utterances while preventing the model from seeing out-of-domain human-readable labels. The serialized chunk `input_text` records the exact normalized text evaluated by ViT5.

## Cache and Reproducibility

Change the pipeline input-format fingerprint from `speaker-colon-text-v1` to a new explicit version. Existing ASR and CAM++ caches remain reusable, while old summaries and titles cannot be mistaken for outputs generated by the corrected formatter. The old completed run remains untouched; the corrected evaluation uses a new run ID.

## Verification

Add regression tests proving that two arbitrary CAM++ labels become `no.0` and `no.1`, repeated labels remain stable, and the generation prompt contains only normalized labels. Run the focused tests, then all Custom_10h tests. Run a small GPU ablation against the same topics and compare literal `Speaker` leakage and judged score with the baseline. Only after a positive signal, execute a new full persisted evaluation run.

## Non-goals

This change does not retrain ViT5 or BARTpho, alter CAM++ clustering, change topic segmentation, or overwrite the baseline evaluation artifacts.
